¿Cómo sabe un GPS dónde está?

Un receptor GNSS escucha señales de satélites que transmiten su posición y una referencia de tiempo. A partir de los tiempos de llegada estima distancias y resuelve su posición tridimensional y el error de reloj. Normalmente necesita al menos cuatro satélites para una solución 3D autónoma.

1 · Satélites

Envían mensajes de navegación y señales con información temporal.

2 · Receptor

Calcula posición, velocidad, hora y calidad de solución.

3 · Microcontrolador

Lee las tramas NMEA por UART y transmite la telemetría.

GPS es el sistema estadounidense. GNSS es el término general e incluye GPS, Galileo, GLONASS y BeiDou. El receptor puede producir tramas $GNRMC cuando usa varias constelaciones.

¿Qué hace un CanSat?

Es un minisatélite educativo del tamaño de una lata de refresco que integra sensores, alimentación, control y radio.

Misión primaria: medir y transmitir temperatura del aire y presión durante el descenso.

GPS: es una opción para una misión secundaria, útil para registrar la trayectoria y localizar el aterrizaje.

La altura GPS no es lo mismo que la altura barométrica. Para una bajada rápida, comprueba frecuencia, retardo y disponibilidad de fix.

Limitaciones reales importantes

Señal muy débil
Interiores, edificios, árboles y orientación de antena pueden degradar o impedir la adquisición.
No confundir exactitud con resolución
Mostrar seis decimales no significa medir con precisión centimétrica.
GPS ≠ comunicación
El módulo recibe señales satelitales; para mandar datos a tierra, tu CanSat necesita un enlace radio separado.

Formatos de la misma posición

Conversión guiada

De NMEA a decimal: el valor 3842.4140,N significa 38 grados + 42,4140 minutos.

Lat = 38 + (42.4140 / 60)
    = 38.7069° N

De DMS a decimal: grados + minutos/60 + segundos/3600, con signo negativo para S/O.

Hexadecimal: no existe una “latitud hexadecimal” normalizada como sistema geográfico. Se puede codificar el valor numérico como entero escalado (×10⁷) o como IEEE-754 float32. Son representaciones de datos, no coordenadas distintas. Hay que conocer escala, signo y orden de bytes.

Los valores son didácticos y simulados. En un receptor real el fix, el HDOP y los satélites son calculados por su firmware; no dependen simplemente de un selector.

Calidad de posición

Sin fix: no deberías utilizar la posición como válida, aunque recibas texto por serie.

2D: solución horizontal; altitud no confiable o no disponible.

3D: solución de latitud, longitud y altura.

HDOP: dilución horizontal de precisión. Es un factor geométrico, no un error en metros.

GGA quality: 0 = sin fix; 1 = autónomo; otros valores indican modos específicos según receptor.

Durante la búsqueda NMEA puede seguir llegando; verifica RMC=A o GGA quality > 0 antes de aceptar una posición.

Estructura general

$GNRMC,campos...*HH\r\n

$ inicio · GN emisor · RMC tipo · *HH checksum hexadecimal.

La cadena NMEA no es hexadecimal, salvo el checksum final. Las coordenadas NMEA se expresan en grados y minutos decimales.

Pregunta: ¿qué ocurre si el GPS tarda 40 s en adquirir señal y el descenso dura solo 90 s?

Conviene probar el tiempo hasta el primer fix (TTFF), la antena y la retención de la última posición válida.

GNDGNDGND
VCCSegún móduloSegún módulo
TX (módulo)RX1 (19)GPIO16 (RX2)
RX (módulo)TX1 (18), opcionalGPIO17 (TX2), opcional
Comprueba la placa concreta: un chip GNSS puede trabajar a 3,3 V, mientras que ciertas placas integran regulador y adaptación de niveles. No apliques 5 V al RX de un módulo de 3,3 V sin verificarlo. Une las masas. UART TTL no es RS-232 ±12 V.

Velocidad serie habitual: 9600 8N1, aunque depende de la configuración del módulo. El Arduino UNO solo dispone de una UART hardware compartida con USB; si usas UNO, considera SoftwareSerial a velocidad baja, con sus limitaciones.

Del CanSat a la estación de tierra

GNSS → UART → MCU
El módulo obtiene la posición y envía mensajes NMEA.
MCU → sensores + procesado
El programa valida fix, extrae lat/lon, altitud y hora, y añade temperatura/presión.
MCU → radio → tierra
La radio transporta telemetría propia. No necesitas enviar todas las tramas NMEA si solo usas unos pocos campos.

Receptores frecuentes en proyectos: placas basadas en u-blox NEO-6M, NEO-M8N o M10; características y tensiones varían según fabricante y placa.

Ejemplo Arduino Mega · lectura NMEA cruda

// Mega 2560: GPS TX -> RX1 (pin 19)
// Alimentación según placa GNSS
void setup() {
  Serial.begin(115200);
  Serial1.begin(9600);
}
void loop() {
  while (Serial1.available()) {
    Serial.write(Serial1.read());
  }
}

ESP32 · TinyGPSPlus (Arduino framework)

#include <TinyGPSPlus.h>
TinyGPSPlus gps;
HardwareSerial GNSS(2);

void setup() {
  Serial.begin(115200);
  GNSS.begin(9600, SERIAL_8N1, 16, 17);
}
void loop() {
  while (GNSS.available()) {
    gps.encode(GNSS.read());
  }
  if (gps.location.isUpdated() &&
      gps.location.isValid()) {
    Serial.printf("%.6f,%.6f\n",
      gps.location.lat(),
      gps.location.lng());
  }
}

ESP32 · MicroPython · UART GNSS

from machine import UART
import time

# Cambia pines según tu ESP32 / placa
uart = UART(2, baudrate=9600,
            tx=17, rx=16)
while True:
    line = uart.readline()
    if line:
        try:
            print(line.decode().strip())
        except UnicodeError:
            pass
    time.sleep_ms(20)

Para obtener coordenadas, usa un parser NMEA que valide checksum y estado de fix. Recibir un texto $GNRMC no garantiza que contenga una posición válida.

Prácticas recomendadas

  1. Leer las tramas y localizar RMC y GGA.
  2. Convertir NMEA a grados decimales.
  3. Mostrar la posición en el mapa y registrar la hora UTC.
  4. Simular la pérdida de fix y descartar puntos inválidos.
  5. Enviar solo los campos útiles como telemetría.
  6. Comparar altura barométrica y altura GNSS.
Para módulos GNSS de 3,3 V, ESP32 suele ser más sencillo en cuanto a niveles lógicos, pero verifica cada placa y evita usar GPIO reservados o de arranque según el modelo.
